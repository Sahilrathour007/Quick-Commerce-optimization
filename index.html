Reorder

Reorder point = average daily sales × lead time + safety stock. Safety stock = z × daily variation × √lead time. On hand is book stock (received + sellable returns − dispatched), so a missed scan cannot hide a shortage. Type a lead time on any row to override the default for that SKU.

Relocation

Which SKUs to move, how many units, and where to, checked against each slot's space and weight limit. Best movers go to zone A, worst movers leave it. Whatever does not fit in a pick slot goes to reserve (back stock) and refills the slot later.

Moves, in order

Do them top to bottom. Moving slow SKUs out of zone A comes first, because that frees the slots the fast ones move into. Each move is one move-out scan at the old slot and one move-in scan at the new one.

How space per unit is worked out

Weight is read when the product is scanned and checked against each slot's weight limit. Space comes from the product's size (length × width × height) where it is on file. Where it is missing, it is estimated from weight ÷ a typical packed density for the category, and marked est.

Categorykg per litreSKUs estimated

Estimates are rough. Chips weigh 0.05 kg per litre and salt about 1.1, so one density per category can miss by 2×. Measure the top SKUs once and enter their size.

Setup

Connect your Supabase project, then label each station's scanner.

Supabase

  1. Create a project at supabase.com.
  2. SQL Editor → paste supabase/schema.sql → Run. Then the same for supabase/seed.sql (products, shelves, opening stock).
  3. Authentication → Users → Add user → Create new user (tick Auto Confirm). Use that email and password below.
  4. Project Settings → API → copy the Project URL and the anon public key below.

Inside the Claude artifact viewer, calls to outside servers are blocked, so this page can only run on demo data here. Host index.html yourself (Vercel, Netlify, or open it from disk) to connect.

How scans reach the map

This site only reads. Your scanners (a handheld app, scanner PCs, or your WMS) write one row into scan_events per movement. The map, reorder list and failure checks are all built from those rows.
